Reading an investigation

The Steps list shows what the agent did, one row per step. Three kinds of labels appear in it:

LabelStands forWhat it isMade by
B1, B2, …Baseline (first check)Automatic checks before the model starts: alerts, metrics, traces, logs, pods and deploys of the affected servicesharness
H1, H2, …Hypothesis (theory)A suspected cause the model writes downLLM
E23, E24, …Evidence (check)One query the model chose, to test a theoryLLM

Evidence numbers continue after the first checks: with 22 B checks, the model's first check is E23.

A theory line

H1 [open] Brief 5xx spike at 06:45 on both gateways comes from agent-call-cmd-service …

"Theory 1: the 5xx spike comes from agent-call-cmd-service." The word in brackets is its status.

An evidence line, read left to right

E34 traces.search [H1] via verbex-datadog: 2203 spans · … 4× 500 PATCH /v1/phone-numbers/{id}
E34check number 34
traces.searchthe kind of query: logs.search, metrics.query, traces.search, k8s.pods, k8s.events, deploys.list, alerts.list
[H1]the theory this check tests (B checks have none)
via verbex-datadogthe connector that answered
after the colonthe result, as one summary line (personal data masked)

How they fit together

  1. The B checks show what looks wrong, e.g. "both gateways have 5xx errors".
  2. The model writes H theories to explain it.
  3. It runs E checks to test them, at most 2 per turn.
  4. It marks a theory supported or ruled out and finishes. The report cites the B and E numbers behind the conclusion, so each claim can be looked up in the steps.

Hover a B, H or E label in the steps to see what it is.

Theory status

openStill being checked.
supportedThe evidence confirms it: the likely cause.
ruled outThe evidence contradicts it: not the cause.

The final confidence (high medium low) is checked in code: a root cause needs at least 2 different kinds of evidence (for example traces and logs), and a missing connector caps it at medium.

Steps

connectThe model and the connectors this run uses (each connector is tested first).
intakeWhat the question is about: service, symptom, time window; for an alert link, the monitor and its environment.
baseline_queryOne first check (B). They run in parallel: every connector, every signal.
triageWhich service looks affected, and why.
investigateOne turn of the model: new theories, its checks (E) and their results, theory status changes.
verifyCode checks the conclusion: cited evidence exists, enough kinds of evidence, confidence.
analyzeFills the agent's analysis fields (if it has any).
reportThe report is written.
stopSomeone pressed Stop.

Controls

▸ WhyUnder an investigate step: the model's own reasoning for that turn (a summary, personal data masked). It is stored with the investigation and deleted with it.
note:Feedback from the code to the model, e.g. a repeated query that was skipped, or a finish that was rejected because it had too little evidence.
StopThe current step finishes (a model call can take up to a minute), then the report is written from the evidence found so far.
One at a timeEach agent runs one investigation at a time. Starting another, or an alert for the same agent, is refused until it finishes or is stopped. Anyone opening the agent's page sees the running one live.

The report

  1. Root Cause: the cause, the theory behind it, and the evidence that supports it.
  2. Impact: affected service, user-visible effect, active alerts, other services that look unusual.
  3. Summary: a short explanation and a timeline built from the evidence.
  4. Evidence: every check with its result; ★ marks the evidence cited for the cause.
  5. Recommendations: next steps. The agent never changes anything.
  6. Investigation Coverage: what was checked, with which connector, and what wasn't.
  7. Confidence & Limitations: why the confidence is what it is, and what could make the conclusion wrong.

A focused question ("show the logs of X") ends with an Answer instead of a Root Cause.
